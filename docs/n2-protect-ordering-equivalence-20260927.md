## 二、逐类控制流证明及边界

5. **management 首连/重连**：壳解析地址、开未连接 TCP，`await protectSocketWithBox` 成功才 `connectorStartWithSocket`；Rust 的 `ProtectedSocketConnector` 每次调用先获取已保护 fd（队列或按需补给），再 dup、设非阻塞、`TcpSocket.connect`，取不到即 dial 失败。初始备用 management fd 先 protect 再 feed；按需新 fd 只有成功保护才 reply。可证明应用内先后顺序，不能证明系统生效。壳侧 `resolveManagementIp` 只在首次 create 前执行，因而不是隧道已建立后的同类自环风险；其系统 DNS socket 的归属与出口仍需另核。[Ability.ets:799-855](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L799-L855)、[同文件:1042](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L1042)、[同文件:2694-2727](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L2694-L2727)、[mgmtsock.rs:335-369](../client/core/src/mgmtsock.rs#L335-L369)。

## 三、跨语言、失败与寿命的未决条件

11. **dup 推论，非平台证明；借用 fd 不变量**：Rust `dup_socket_fd` 复制 fd，`connect_protected` 在副本上 connect。按 POSIX/Linux 常规，dup 与原 fd 指向同一 socket/open-file description；因此**若** HarmonyOS protect 标记附着于该 socket 对象，保护原 fd 后 dup 的 connect 应受保护。SDK 没有明示标记附着和跨 dup 行为，须以原 fd/dup 关联及物理出口证实。核心的 management、ICE、WG feed 队列保存的是**借用的 fd 号而非 dup**；其安全不变量是“壳侧永不 close 已 feed 的 fd”。如果 close 后号码被复用，核心可能 dup 到未保护的新 socket 并 connect；`EISCONN` 分支甚至能收养已连接 socket。修复首连 protect 失败的 fd 泄漏时**只能 close 尚未 feed 的 fd**；按需补给 `socketSupplyReply` 则在返回前由核心同步 dup 成 owned fd，原 fd 在 reply 后关闭是另一种契约。[mgmtsock.rs:175-180](../client/core/src/mgmtsock.rs#L175-L180)、[同文件:335-365](../client/core/src/mgmtsock.rs#L335-L365)、[ice.rs:651-656](../client/core/src/ice.rs#L651-L656)、[wg_device.rs:1824-1826](../client/core/src/wg_device.rs#L1824-L1826)、[socket_supply.rs:136-154](../client/core/src/socket_supply.rs#L136-L154)、[SDK:228-244](/home/worker/harmonyos/command-line-tools/26.0.0.821/sdk/default/openharmony/ets/api/@ohos.net.vpnExtension.d.ts#L228-L244)。
12. **Promise resolve / timeout 的精确强度**：正常模式下 `connection.protect(fd)` resolve 置真，reject 或 5 秒计时盒超时为假，调用方仅在真后交付，构成应用控制流顺序，不直接证明内核路由策略完成提交。平台 Promise 可能在超时后迟到；按需补给回复 `-1` 并 finally 关闭原 fd，核心过期请求不接受。若 protect 迟到 resolve 时该 fd 号已被重用，最多额外保护一个重用该号码的 socket，不会由该失败请求交付未保护 fd 而外泄；此竞态登记待测。初始 management/signal、备用 fd、ICE/WG 部分失败路径只中止 feed/启动，不能声称失败 fd 均立即关闭；清理必须遵守第 11 条已 feed 的借用 fd 不变量。若设备发现 resolve 领先保护生效，应停门返回 T0，不以任意睡眠补救。[Ability.ets:3262-3312](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L3262-L3312)、[同文件:2631-2682](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L2631-L2682)、[socket_supply.rs:136-164](../client/core/src/socket_supply.rs#L136-L164)。
13. **fail-closed 的限定含义**：按需 reply 仅 `result == "protected"` 且 fd 有效时 dup；无供给、超时、过期或关闭报错，management source 空队列与 relay 无供给都不降级裸连。初始 signal 保护失败停 connector、不 create；WG 失败 destroy 已建 VPN；ICE 部分池失败只是候选变少，不能泛化成所有分支“关闭整个 VPN”。故故障注入分别验收“该失败 socket 不发包”与各场景预期状态。[socket_supply.rs:100-115](../client/core/src/socket_supply.rs#L100-L115)、[同文件:136-164](../client/core/src/socket_supply.rs#L136-L164)、[mgmtsock.rs:145-149](../client/core/src/mgmtsock.rs#L145-L149)、[Ability.ets:896-905](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L896-L905)、[同文件:3080-3111](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L3080-L3111)。
14. **诊断开关、无开关端点排除及生命周期**：`protectDeviationRouteExclusion` 可以在未调用 protect 时返回真，不能以布尔值或日志代替证据。证据前置条件：`filesDir/netbird-protect-deviation` 偏离文件不存在，日志无 `VPN_PROTECT_DEVIATION_ARMED`，S2-S6 诊断开关全关，`protectProcessNet` 与 `blockedApplications` 不启用。端点排除目前**没有关闭开关**：初次 `deriveEndpointExclusions` / `withEndpointExclusions` 和 recreate 的 `withEndpointExclusions` 无条件生效；N2 证据轮必须关闭端点排除（T0 条件④），需先另行修改代码加开关，本文件不实施。历史 `40/40 resolved` 与 bypass 观察均为 `is_evidence=false`。recreate 在 2459-2514 行仅 destroy 旧连接、创建新 `VpnConnection` 并换 TUN，**不重拨**：已建立的 management/signal/relay TCP 流、ICE 检查 socket、WG socket 都带着旧保护跨过 destroy/create，不只是 WG。另有待修缺陷：`startSocketSupply(connection)` 与 `startIceSocketTopUp(connection)` 的定时器闭包固定首代 `VpnConnection`，recreate 后未重启，按需补给与 ICE 补池向旧对象 protect，可能 reject 导致重连饿死，也可能 resolve 但无效而交付未保护 socket；计划改为**调用时读取当前连接对象、recreate 期间拒绝**，单列 N2 测试格。[Ability.ets:720-743](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L720-L743)、[同文件:936-949](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L936-L949)、[同文件:2410-2411](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L2410-L2411)、[同文件:2459-2514](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L2459-L2514)、[同文件:2608-2659](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L2608-L2659)、[同文件:3117-3157](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L3117-L3157)、[同文件:3262-3274](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L3262-L3274)、[NetBirdVpnConfig.ets:202-216](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnConfig.ets#L202-L216)。

## 四、条件结论与预注册的 N2b 物理清单

15. **结论**：上游四份原件已核，但 `WithContextDialer` 接线未核。若目标设备确认 protect Promise resolve 后策略对新报文已生效、原 fd 和 dup 指向的 socket 享有同一保护；**create() 前 protect 的 socket 在 create 后对已建连接持续有效**（management/signal protect 与 connect 都早于首次 create）；**全部存活 socket**（management/signal/relay TCP、ICE 检查、WG）跨 recreate 的 destroy/create 持续有效；生产外层 socket 枚举无漏项、失败不裸连、切网保护持续，且第 14 条的端点排除关闭，则“壳 open → await protect resolve → feed → native dup → connect/send”在**逐 socket 首包前保护、失败不发送未保护报文**这一行为上可与上游相比。它不与同步 API 形式或 bind 顺序字面同构。任何前提未能证明，保持待决或 `deviation/UNSAT`，不得宣称 N2 pass，不启用路由排除/进程保护替代；主机测试不能证明设备行为。[Ability.ets:842-855](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L842-L855)、[同文件:925-1042](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L925-L1042)、[同文件:1131-1139](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L1131-L1139)、[同文件:2459-2514](../client/entry/src/main/ets/vpnextensionability/NetBirdVpnExtensionAbility.ets#L2459-L2514)、[治理:39-43](native-nx-governance.md#L39-L43)、[同文件:159-163](native-nx-governance.md#L159-L163)。
