## 一、Q1 · E4 范围管辖（三席 3/3 收敛）

**E4 的义务清单以 `docs/roadmap.md:348` 的原义为准**：fd、地址、路由、DNS、MTU、IPv4 及声明范围内 IPv6 的配置与清理。

- 基础决议 §二.8 的括注「E4（TUN 配置/地址/MTU/IPv4/清理）」是**映射助记标签，不是范围再定义**；同句「映射不免除义务」本身即排除以括注遗漏为豁免依据。E6 括注「双向泵」相对 `roadmap.md:350` 同属缩写，可对照。
- 基础决议相对 roadmap **优先的是映射去向**（E4 由 N 门承接，不再等 E8 `OPEN` 后的 R2/R3），**不是**用括注重写 E4 清单。`roadmap.md:36,278,280,361,688` 的 R2/R3 承接条款作为最终兜底保留。
- **N1a 不承担 E4**：N1a 无真实 TUN，E4 物理面全部在 N1b 与下列指派门。此为对基础决议 §二.8「映射到 N1a/N1b」的澄清。

## 二、Q2.1 · tun fd 背压不可诱发时的处置（T0+ 终裁，采纳甲席）

1. C7 三态（`induced` / `not-triggered` / `fail`）维持。有界时间盒内未诱发 → 记 `not-triggered`，**不构成 fail、不构成 blocked、不阻止 overall pass**。
2. **主张上限逐字写死**：本门任何证据、汇总或后续引用**不得出现「tun fd 背压已验证」或等价表述**；证据措辞固定为 `attempted, not induced on this fd`。`not-triggered` 记录**必须携带定量尝试参数**（累计写入字节、写调用次数、时间盒起止单调时钟），缺失按字段缺项处理（C11 fail）。
3. **§二.2 背压义务在 `not-triggered` 结局下不关闭**，登记入开放义务台账（§七）。关闭条件仅限：(i) 同一冻结元组上后续具名 campaign 在**真实 tun fd** 上观测到 `induced` 并落盘；或 (ii) 新 T0 书面显式放弃。
4. 同一口径**逐字适用于 FD-L5 部分写**观察项。
5. 为 (i) 提供现实载体：后续在同一元组上行使真实 tun 写路径的门（至少 N6、N7）登记被动观察字段 `tun_eagain_on_write_observed` / `tun_partial_write_observed`（观察项，不设门），任一观测到即触发义务关闭登记。
6. r1 `n1b-gate-plan.md:174`、`:196` 中与本裁定一致的既成措辞，由本决议**追认**为 T0 授权文本。

**否乙席（overall blocked）之理由**：本门 blocked 语义限于**无法求值**（前提不成立/环境/不可观察），而有界 write-until-EAGAIN 是**已完成的测量**，产出确定的负面观察，不属不可求值。在基础决议 §三单次不重试约束下，该规则会把平台上完全正当的良性结局（缓冲从不填满）自动转化为烧掉一个不可复用 ID + 回 T0，而 T0 面对「诱发不出」无任何新指令可下——纯损耗。

**丙席不完整**：与甲同在「不阻止 pass」，但未回答义务归宿；义务只能显式关闭或显式移交，不得随降级措辞消失。

**N1a C5 先例（`n1a-gate-plan.md:32`）的作用域**：其结论不自动外推到真实 tun fd（基础决议 §二.1/§二.2 分立），但其法理（有界负面观察 ≠ fail ≠ blocked + 主张降级）成立；本决议**显式**将该法理扩展到 tun fd，外推障碍由此解除。

## 三、Q2.2 · shutdown unblock 与「探针不得自建线程」的结构冲突（T0+ 终裁，采纳甲席框架 + 并入乙席测量规格）

**事实认定（三席一致）**：r1 的 FD-P1（`n1b-gate-plan.md:95`，destroy 后对副本 500 ms 有界 `poll`）是**恒真的**——有界 poll 按时返回可完全由自身 timeout 造成；且 r1 冻结全同步执行（`:63`）、tun fd 非阻塞（`:61`）、C9 静态断言禁线程（`:176`），destroy 发生时根本不存在已进入等待、需被解除的操作。`:61` 把非阻塞写成 shutdown unblock 的「可测前提」是概念颠倒。

1. **FD-P1 现文废止**——恒真判据不得保留。N1b r2 中该义务项记 `not-measurable-under-sync-nonblock-probe`，overall **不**因该项未测而 fail。
2. **现阶段不开线程、不从 §二.2 删除**。N1b 的 C9 静态断言不因 DISC 而松动。
3. DISC 重拟稿新增 waiter 观察项 **D-W**：探针创建**恰好一个登记在册**的 worker，于 destroy **之前**经预注册 barrier/marker 确认进入对 dup 副本的**有界**等待（有界以限定 watchdog 暴露窗口），随后 `destroy()`，以单调时钟登记 poll 返回时刻、事件集、与自身 timeout 的区分、join 结果、该线程是否被 watchdog 杀。**全部结局均为观察事实，不设 pass 条件。** D-W 与 D6 **共用同一 destroy 事件**（waiter 先入等待 → destroy → 主线程 D6 同步尝试 + D-W 结局采集），无需第二次 destroy。
4. **「destroy 关闭原始 fd」不得预设为「必然唤醒 dup 副本上的 poll」**——唤醒与否本身即待发现事实（Linux 通用语义下 close 单个 fd 不必然唤醒同 open-file description 上其他 fd 的 poll；本元组未核实）。
5. **预授权两条关闭路径**，由 DISC（含 D-W、D6）结果择一，**不再为此单开 T0**：
   - **① D-W 显示**恰好一条登记 waiter 可存活、可确认进入等待、destroy 语义可与自身 timeout 区分 → N1b r2 纳入以该 waiter 实测 shutdown unblock 的**真判据**；C9 改为「除该唯一登记 waiter 外禁止自建线程」。
   - **② D-W 显示**并发 waiter 不可执行（被 watchdog 杀 / 无法确认进入等待），**或** D6 显示 destroy 后同步不可观察 → shutdown unblock 与其余不可观察 post 子项**转移至 N6/E7 短循环**承接（基础决议 §二.8 已把 E7 映射到 N2/N6），作书面登记并援引 N0 停止条件 3（「真实 VPN fd/protect 不可满足」）题域，登记入台账（§七）。**不得由起草人自行删除或静默降格。**
6. 无论走哪条路径，最终实测判据设计**须同时满足**四项技术要求：显式 cancellation 机制、进入等待的 barrier 确认、单调时钟区分 fd 事件唤醒与自身 timeout、有界 join。外层 watchdog 只可判定 hang，**不得充当成功唤醒的原因**。

**否乙席（即时开受控 worker）**：其设计押注 U7（watchdog 对 worker 的行为）与「destroy 必唤醒 dup poll」两个本元组未实测前提（后者乙席自己也作了警告），等于把发现工作放进单次不可重试的正式门——正是本决议 §四要消除的结构。其**测量规格是三席中唯一技术完备的**，整体吸收为第 3、6 条。

**否丙席（正式移出 + 「本元组不可测」）**：该措辞过宽——不可测的根源是 r1 冻结的**全同步/非阻塞探针架构**，不是元组本身；乙席方案说明同元组可能可测。正式移除且只留「待平台变化」这一无法审计的重开触发，会制造无归宿义务，与「映射不免除义务」冲突，并放弃了 DISC 数据本可廉价解锁的 r2 真测机会。其「义务保持开放」原则由台账承接。

## 四、Q3 · N1b-DISC 发现门授权（三席 3/3 有条件授权；拆 ID 经 T0+ 终裁）

**授权**在 N1b 正式门之前插入门代码 `N1BDISC` 的前置发现 campaign。此为基础决议 §二.10 的一次门顺序变更，并构成 §三 pre-E8 native 物理例外的一次新行使。

**同时否决**材料包 §4.2 的 D1-D7 草案全文（三席一致）。

### 4.1 拆 ID 的论证与代价（逐字载入）

批准独立 DISC 使用**第二个** AUTH/pair 与 evidence ID。理由：

- 基础决议 §二.7 要求判据在测量开始前预注册。U1-U7 未知时，功能判据只能写成对未知平台事实的条件分支或赌注——**两轮五席全部 fail 已实证**该判据在此信息状态下写不稳。
- **结局不对称**：DISC 无功能 fail，任一事实为负仍继续收齐其余，一次执行确定性收获全部七项；合并方案在正式门冻结顺序（S8）下**首个为假的前提即终止**、事实收获截断，且 U3 为假会以**功能 fail 形态**烧掉正式门。
- **代价**：拆分**保证**消耗两个 AUTH/pair 与两个 evidence ID；合并方案在七个 U 全真时可省一个 ID。在 §三不可逆消耗约束下，裁定确定性收齐事实 + 正式门在已知前提下冻结，**优于**以七项未实测前提之合取换省一个 ID 的期望收益。
- **选项 C（同一 N1b campaign 内分阶段发现）登记为「已考虑、被否」**，不得从本决议删除。

**终裁自陈的不确定性（保留登记）**：上述优越性论证依赖对 U1-U7 为真概率的**未量化先验**；若七项实为平台常态行为，合并方案本可高概率省下一个不可复用 ID。这是**风险偏好判断，不是测量结论**。用户已在知晓该代价面的前提下批准。

### 4.2 DISC 的证据身份与 verdict 语义

- **门代码 `N1BDISC`**；ID 形态 `AUTH-N1BDISC-PHYS1API26-<YYYYMMDD>-0001` / `N1BDISC-PHYS1API26-<YYYYMMDD>-0001` / `EV-N1BDISC-PHYS1API26-<YYYYMMDD>-0001`。
- **`verdict` 枚举不新增任何取值**，仍限 `pass | fail | blocked | invalid`。材料包的 `verdict: collected` **非法**（`collected` 属 `record_status`）。
- DISC 的 `verdict` **只对基础设施与完整性求值**：`pass` = 发现协议按冻结顺序跑完且事实已登记落盘（**事实本身可为负面**）；`fail` = 基础设施正常前提下探针未完成预注册采集、破坏冻结顺序、未增量落盘或封签失败；`blocked` = 仅限外部基础设施不可达；`invalid` = 污染、哈希不一致、白名单外命令、跨 attempt 拼接。
- **平台行为「不如预期」永远不是 `fail`，也不是 `blocked`。**
- 全部平台事实以三态逐项登记：`observed-true` / `observed-false` / `unobservable`。
- `record_status` 沿用现有语义：执行后 `collected`，独立审查合格后 `reviewed-pass`。
- **硬约束**：DISC 的 `verdict: pass` **不得在任何后续文档中被引用为平台行为结论或任何门的功能结论**。
- **schema 扩展是 ID 分配的前置**：N 门代码与发现型记录形态须由 schema 持有人先行登记（`evidence-schema.md`），完成前不得分配 DISC 证据 ID。

### 4.3 DISC 重拟稿的强制条件

1. 否决 v1 的 D1-D7；重拟后须并入：原 D7（watchdog 观察）**重排至 destroy 之前**；U3 的决定性数据**并入受控包链路**而非依赖「内核自然产生的包」；D2 增补「实际生效 MTU 的可观察性」登记；**D-W**（§三 3）。
2. **D2 不得声称产出「实际 interface 名」**——`create(config): Promise<number>` 只返回 fd；D2 至多验证预注册 interface 输入是否被接受，`create` 拒绝是事实不是 fail。
3. **D1 不得夹带门结论**：D1 的加载事实只能作为基础决议 §二.8 所需 arm64 同核心加载证据的**候选引用**，N1b 的 C1 仍须执行。
4. 每项事实完成即发射 marker 并**增量落盘**，任一后续步骤崩溃不得损失既得事实。
5. 探针可用 POSIX `read`/`write`/`dup`/`fcntl`（E3 探针契约与本门 dup 副本契约不同，**不可混引**）。DISC 本 campaign 除 D-W 的唯一登记 waiter 外不得开线程。
6. 沿 **G0 十三门流程范式**（`g0-go-arm64-physical-probe.md:174-188`：host-only 同步 → 两次 ID 消费审计 → freeze → 静态审查 → 目标绑定 → ready freeze → reviewer record → 最终 freeze → selftests → DryRun → DryRun 独立审查 → 单次 Live 不 retry），**适配沿用，不照抄 G0 专属 ELF/Go 输入**。
7. 重拟稿须经**跨厂商隔离独立审查**，且不得由主会话自身模型家族充任（沿 `n1b-gate-plan.md:233`）；**0 blocker** 方可请用户授权。
8. DISC 与 N1b 正式门**不得共用同一 AUTH/pair**。
9. **本决议不构成设备 Live 授权**：物理执行仍须用户显式授予全新 AUTH（基础决议 §三：单次执行、不重试、不换 ID）。

### 4.4 DISC 结论的使用边界

DISC 事实只作为 N1b r2 判据的**预注册设计输入**，**不构成** fd 合同、数据面、E4 或任何门的功能结论。N1b 仍须在本门 campaign 内复测其数据面相关观测；**禁止**「DISC 已见故 P1 跳过」。仅当 DISC 达到 `reviewed-pass` 且目标元组、VpnConfig、进程模型、SDK 与相关哈希与 N1b 一致时，其事实方可进入 N1b 预注册。

## 五、E4 中「声明范围内 IPv6」的去向（T0+ 终裁，新立场）

1. **N1b 记 `N/A-undeclared`**：本门冻结 VpnConfig 无 IPv6 地址/路由，SDK `isIPv6Accepted` 默认 `false`，声明范围为空集，本门无可核验对象。此记法**不构成范围削减**，因义务经第 2、3 条显式安置。
2. **触发条款**：任何后续门的冻结配置一旦声明 IPv6 地址或路由，该门**同时承担** E4 IPv6 核验义务，并须在其判据预注册中显式列出；缺列即审查 blocker。
3. **【对基础决议 §二.5 的加法修正】** `r0-charter.md:94` 的首轮 IPv6 义务（「IPv6 在首轮实现中**必须探测并记录能力与失败边界**，但不作为首个 0.x 的强制功能」）显式指派 **N6** 承接为**观察类探测项**（非门控）：在真实自托管 oracle 环境下探测本元组声明 IPv6 的能力与失败边界并落盘；**结果不影响 N6 pass**。N6 判据起草时缺该项即审查 blocker。此为按 §二.10 完成的范围加法调整，不构成削弱。
4. GA 级 IPv6 声明维持章程原文（另行动态调整锁定范围/元组/矩阵/SLO）。E4-E7 完整义务最终兜底为 E8 `OPEN` 后同一具名设备的 R2/R3，不因 N 门指派而改变。

**否乙席（N1b 承担最小 IPv6 切片）**：向单次不可重试的冻结配置加入 IPv6 声明会引入 `isIPv6Accepted` 行为等新的未实测前提，与 §四消除赌注的方向直接冲突，且章程明文 IPv6 非首个 0.x 强制功能。**甲席单独不完整**（未安置章程无条件探测义务），**丙席方向正确但缺章程事实与指派对象**，均由第 3 条补齐。

## 六、C10 聚合后果与「不可 pass 僵局」出口（T0+ 终裁，采纳甲席）

1. **C10 的聚合后果拉回 T0 管辖**。起草人「属判据层可自行修订、不在表决范围」的分类**不成立**——改变 `blocked` 的聚合后果即改变本门的可通过性条件，属基础决议 §二.10 的门范围/阈值变化。
2. **实体维持三席结论**：C10 `post-destroy-unobservable` → **overall `blocked`**（`n1b-gate-plan.md:177`、`:196` 相应修订）。登记：该收紧经三席独立确认并经终裁追认，**构成收紧而非削弱**。
3. **预授权三分支出口**（与 §三、§四联动）：
   - **a. U4 为真**（DISC D6 证实 destroy 后可同步观察）→ r2 保留 C10 及 overall-blocked 规则。
   - **b. U4 为假** → r2 **不得**保留押注 U4 的 post 门控子项；post-destroy 义务按 §三 5-② 转移 N6/E7 并书面登记，C10 重划定为 DISC 证实可观察的子集——**僵局不成立**。
   - **c. DISC 判 U4 为真而 N1b live 仍现 `post-destroy-unobservable`**（DISC↔N1b 矛盾）→ overall `blocked`、消费 ID、**强制回 T0** 并登记矛盾本身；预授权处置仅限 §三 5-② 转移或 T0 显式放弃，**禁止以判据循环改写另开执行**。
4. **不拉回**：时间盒表补全与 P2 负面判据的样本数/完整窗口属基础决议 §二前言「细化证据方法」（P2 样本窗从未被 T0 锁值），不构成 §二.10 阈值变化；但两项**必须在 r2 冻结前补全并经独立审查**，缺失即审查 blocker。

## 七、【新条款】开放义务台账

§一、§二、§三、§五四处分歧的共同根因是「去向另行治理指派」**无结构化载体**——义务靠散落括注传递，每次都长成新的 T0 争议。

**建立单一登记表** [开放义务台账](open-obligations-ledger.md)：逐条列出未被当前门关闭的 §二.2 / E4 义务，字段为义务原文出处、持有门、关闭触发、当前状态。变更仅经 T0 或本决议已预授权的路径。台账把「映射不免除义务」从原则变成**可机械审计的检查项**。

任何门的判据预注册与记录级审查，须核对台账中归属本门的条目；遗漏即审查 blocker。

## 八、自洽性认定

§二（义务开放）× §三（义务不删除）× §六（C10 收紧）三者叠加**不产生死锁**。§四的 DISC 前置使 U4 在 r2 冻结前已知：U4 真则 C10 可真实求值，U4 假则 post 子项依预授权转移、C10 重划定，抵押解除。

**现实通过路径**：DISC 重拟（含 D-W、重排、代价登记）→ 跨厂商独立审查 → 用户授权 → DISC 单次执行收齐 U1-U7 与 waiter 事实 → r2 依**实测事实**冻结（择 §三关闭路径、划定 C10）→ 独立审查 → 用户授权 → N1b 单次执行。届时前提类 blocked 已被 DISC 排干，剩余失败模式是真功能失败（握手、双链完整性）。

唯一残余 blocked 风险是 §六 3-c 的 DISC↔N1b 矛盾分支，已预授权处置。

## 九、提交瑕疵与起草人偏向登记
