# 任务：核对三台 peer 的网络/账号归属，并给出最小修复（同中继对照实验被网络归属问题阻塞，零配置改动）

## 背景（一句话）

我们在开发 **HarmonyOS 平台的自研 NetBird 客户端**（非官方客户端），正在你们的生产实例上做「同中继修复前/后」受控对照实验，但被一个网络归属问题卡住：我们的**主机侧对端** `ohos-ab-host-1`（overlay `100.108.126.29`，用你们最新那批一次性 key 之一注册）的网络图里只有 3 个 peer——`100.108.171.38`、`100.108.162.237`、`100.108.156.116`；而我们的**设备** `ohos-smoke-1`（overlay `100.108.144.165`，用更早的一把 key 注册）**不在该网络图里**（反向亦不可见），于是对端持续以「relay peer offline」拒收设备的 relay 帧（窗内计数 24100→25200），实验无法进行；补充事实供判断：更早用另一把 key 注册的 `ohos-relay-1`（overlay `100.108.252.167`）**曾**与你们的 `net-host` 建立 WireGuard 会话（说明该 peer 与 `net-host` 同网络），`ohos-ab-host-1` 看来亦与 `net-host` 同网络（已有 1 条 WG 会话）——**我们的判断**：`ohos-smoke-1` 与 `ohos-ab-host-1` 可能被注册到了**不同的账号/网络**（或 `ohos-smoke-1` 已被清理、设备重注册后落在别处），请按下表核对并给出最小修复。

| # | 事项 | 要求 |

- **只读核对 + 上述最小动作**：**不要**重启服务，**不要**改动 relay / signal 配置。
