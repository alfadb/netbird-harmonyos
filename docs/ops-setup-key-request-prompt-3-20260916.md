# 任务：为自研 NetBird 客户端受控对照实验索取第三把一次性 setup key（用于我们主机侧的对端，零配置改动）

## 背景（一句话）

我们在开发 **HarmonyOS 平台的自研 NetBird 客户端**（非官方客户端），它已在你们的生产实例上完成 relay 数据面验证——设备侧与**你们的对端 `net-host`** 成功建立 WireGuard 会话（我方观测 `wgSessions=2`、`vpn-tun RX` 由 0 增至 4624 字节；你们侧亦记录到 `created new wgProxy` 与 0.08 秒首次握手）；现在我们要做一次**受控对照实验**（同一中继下「修复前 / 修复后」对照），需要一个**由我们自己控制的应答对端**——否则「对端是否在线」会成为无法排除的混杂因素（上一轮正是因为对端缺席，导致对照未收敛）；该对端将由我们运行在**自己的主机**上（我们自己实现的客户端），仅用于这次实验，因此需要一把新的一次性 setup key。

## 需要交付的东西

| # | 事项 | 要求 |
|---|---|---|
| 1 | **新建一把一次性 setup key** | `usage_limit = 1`：只用一次，只注册这一台设备（即我们主机上的应答对端） |
| 2 | **有效期** | 短期，例如 **24 小时内**过期 |
| 3 | **peer 命名建议** | 把该 peer 的主机名设为 **`ohos-ab-host-1`**，便于我们在 peer 列表里识别，也便于你们事后清理 |
| 4 | **key 的传递方式** | 通过**安全渠道**交给我们：例如直接在对话里发；**不要**写进代码仓库、公开渠道或工单系统附件 |

## 重要约束

- **只读要求**：除「新建这把 setup key」外，**不需要**改动 management / signal / relay 的任何配置。
- **用完即回收**：实验结束后我们会第一时间请你们 **revoke** 这把 key。请留意官方 NetBird 语义：**revoke setup key 不会踢掉已经注册成功的设备**——若要移除设备，需要在 dashboard 上**另行删除对应 peer**。届时我们会一并申请删除 `ohos-ab-host-1`，以及早前实验遗留的 `ohos-smoke-1` / `ohos-relay-1`——**是否现在清理由你们决定**，也可以等我们实验结束后一起处理。
- **不要**向我们索要或让我们提供任何私钥/令牌；我们也不会提供。

## 备注（我们这边会做什么）

这把 key 只用于注册 `ohos-ab-host-1` 这一台对端；实验完成后我们即请你们回收，不做其它用途，也不会据此对你们的部署做任何变更。
