# 开放义务台账

最后核验：2026-08-31 ｜ 依据：[ADJ-T0-N1B-20260831-0001](native-nx-n1b-adjudication.md) §七

本台账登记**已由治理设定、但尚未被任何门关闭**的义务。设立原因：此前义务靠散落括注与「去向另行治理指派」传递，无结构化载体，导致同一批义务在每轮判据审查中重新长成 T0 争议（`ADJ-T0-N1B-20260831-0001` §一、§二、§三、§五四处分歧同源于此）。

本台账把基础决议 §二.8「**映射不免除义务**」从原则变成**可机械审计的检查项**。

## 使用纪律

1. **判据预注册**时，起草人须核对本台账中归属本门的条目，并在判据中逐条给出处置（承担 / 观察 / 转移去向）；遗漏即审查 blocker。
2. **记录级审查**时，审查席须核对本门声称关闭的条目是否满足其「关闭触发」；不满足即不得登记关闭。
3. 条目的**新增、修改、关闭**仅经 T0 决议，或经既有决议**已预授权**的路径（预授权路径须在「关闭触发」列写明依据）。
4. 关闭时不删除条目，改「当前状态」为 `closed` 并补登记关闭证据 ID 与日期。**历史不改写。**
5. 「持有门」为负责推进该义务的门；`unassigned` 表示尚无持有门，**这本身即是须在下一次相关 T0 中解决的缺口**，不得长期留白。

## 状态取值

| 状态 | 含义 |
| --- | --- |
| `open` | 义务成立、尚未被任何门关闭 |
| `pending-discovery` | 处置方式取决于尚未采集的平台事实，关闭路径已预授权 |
| `closed` | 已由具名证据关闭（须登记证据 ID 与日期） |

## 不在本台账范围

- 已由具名门正常承担、且该门判据已覆盖的义务——它们由该门自身的判据与双轴状态管辖，不重复登记。
- R0 章程的 GA 级声明（如 GA IPv6 支持）——须另行动态调整锁定范围、目标元组、测试矩阵与 SLO，不走本台账。
- 历史 evidence 与既有判定——一律不改写。
