# N2 真机证据预注册草案（2026-09-27）

> **DRAFT / 未生效 / 非设备授权**。本稿仅供独立审查与主会话拍板；判据、实现与执行器须在任何 N2 正式采集前冻结，经独立审查、用户明确批准并按仓库治理登记后才可能生效。本文不签发 campaign，不允许连接设备、安装、采集或引用既有诊断轮作 N2 pass。N2-H 已休眠；历史 0034/0037 的 `is_evidence=false` 观察只用于设计，不追认为 N2/N6 证据。若存在未覆盖的生产外层 socket，本轮最多 `UNSAT/待决`，不得把已测子集外推成 N2 通过。

## 1. 判定对象与冻结边界

N2 比较的是**每一个实际向 VPN 外发送的 socket**：其可观察的首次 connect/UDP send 之前，`VpnConnection.protect(fd)` 已成功且生效；后续 fd dup、`VpnConnection.create`、recreate、切网之后仍按规定出口走物理网络；失败则该 socket 不发未保护的外层包。应用层 `protect` resolve、布尔状态、收发成功、TUN 计数或单方主机回执都不能单独证明这一点。先审阅[时序等价论证](n2-protect-ordering-equivalence-20260927.md)，并把其条件作为物理实验待证项，不称已等价。独立登记 N2 结论和 N6（内层隧道实际工作、路由/默认路由就绪）结论；可以共用同一轮原始资料，但不能用 N6 成功代替 N2。

预注册冻结元组：设备型号与序列脱敏标识（预期 PLA-AL10，执行前核准）、完整固件/SDK、HAP/core/执行器/判定器的 SHA-256、应用与 VPN 包名、配置摘要、授权号、时间/时区、Wi-Fi/AP/运营商、物理网络句柄及源 IP、VPN 网络句柄与 `vpn-tun`、控制面/relay/DNS/STUN/peer 当轮实际地址与四元组、overlay 地址、服务器版本/日志可见性。历史设备 overlay `100.108.144.165` 与主机 peer `100.108.126.29` 仅为预期核对值；IP/端口和 NAT 映射须当轮重新发现并冻结，不将历史值当证据。应用日志仅输出请求 ID、socket 生命周期 ID、fd 与 dup 关联、目的端类型/脱敏地址、动作时刻/结果，不输出密钥、token、证书内容、报文敏感载荷。每个证据格记录原始文件路径、SHA-256、来源、取样时钟校准及缺件原因。

## 2. 流量类与覆盖矩阵

| 类别 | 首包/所有者及必须观察的变体 | 首连与恢复刺激 |
| --- | --- | --- |
| M 管理 TCP | 壳供给的初始/备用 socket、队列耗尽后的 `purpose=management` 每次重拨；解析独立归 DNS | 初连、断流后真实新 dial、断网与换网 |
| S 信令 TCP | 初始 feed、`purpose=signal` 重连/重注册 | 初连、真实重拨、切网后注册 |
| R 可选 relay TCP | 仅 opt-in 开启时每次 `purpose=relay` 新 socket；`rels://` 为 TLS/WSS，握手、重连和数据要归到同一身份 | 首连、断流重连、切网后重建，确实收到 relay 下发 |
| D 受保护 DNS UDP | `purpose=dns` 每个服务器尝试独立 fd：生产 relay/STUN 与管理/信令恢复域名；初始壳侧管理/信令解析另列盘点，不擅自称受保护 | 首次查询、重试/超时换 resolver、切网后物理 DNS 更新 |
| I ICE/STUN UDP | 初始未绑定池、后续补池、ICE 检查与 STUN 查询，记录选中本地 socket 与目的端 | gather、check、重试、切网后新候选 |
| W WG 外层 UDP | `wg_fwd_open` 的 base socket 和 ICE 选中后交给 WG 的本地 socket/dup，分别标识，不用一个覆盖另一个 | 首次 handshake/keepalive、选中端点变化、切网重建 |

M/S 初始解析若由壳侧系统 resolver 发出，必须在 create 前后分别盘点归属；已建 VPN 下不可持有并保护的系统 DNS 不可并入 D 的成功数，标 `deviation/UNSAT`，回 T0 和用户裁决。IP 字面量不产生 DNS 包，记录 `not exercised` 而非 D pass。R 必须具备真实 opt-in 配置和可验证会话，否则 R=`UNSAT/not exercised`，全量 N2 不通过。TURN、relay QUIC/UDP、IPv6 外层当前 `not implemented`，分别记能力边界，不借已实现 TCP/IPv4 的通过声称其 pass；若部署确实启用或发现该流量，先停测并更新库存/设计。

矩阵的行是 M/S/R/D/I/W（W-base 与 W-selected 分开），列为：(a) 初连（区分 create 前保护且连接持续到 create 后）；(b) 控制面/relay 断流的**新 socket**重连或 DNS/STUN 重试；(c) Wi-Fi→蜂窝与蜂窝→Wi-Fi 的物理切换（两向各自成格，须有真实蜂窝）；(d) 正在承载流量时 `destroy/create` 受控 recreate，观察**所有仍活着的 TCP/UDP socket**跨代持续出口，并触发新补给/ICE 补池；(e) 最终 VPN 撤销，先停止 connector/发送者并销毁相关 socket、再 destroy，另观察撤销后是否有漏出的旧外层 socket；(f) 各类别可触达的拒绝、超时、迟到 resolve 失败注入。不是每格都能在一次会话中可靠产生；逐格写 `exercised/pass/fail/invalid/UNSAT/not-implemented` 和原因，不能用空闲期间 TUN=0 算通过。create 前没有 TUN 的首次 TCP 阶段只能证明时序与物理出口，必须追加 create 后沿用已保护连接的有效刺激及有覆盖路由的阶段；不可只靠 pre-create 的天然 TUN 缺席。

建议独立审查前冻结最小刺激数：每个**可操作**正向格至少三个可逐事件识别的实际发送事件（同一存活 TCP socket 可重复使用，逐事件标记不同）、正控至少三个已入 TUN 的标记事件；失败注入每个指定故障分支至少一次且必须观测到故障确实触发。数量仅是样本充分性条件，不把统计零泄漏当成无条件安全证明。无法自然触发的长连接重连格通过**授权内**受控断流实现，不把应用重启冒充同一存活 socket 的跨 recreate。

## 3. 路由覆盖与旁路关闭

正式 N2 窗口：不存在开发期 `netbird-protect-deviation` 文件，日志无 `VPN_PROTECT_DEVIATION_ARMED`；端点 `/32`/`/128` 排除关闭，`protectProcessNet` 关闭，`blockedApplications` 未设置，S2–S6 诊断开关及诊断捕获路由全关。采集实际下发的 `VpnConfig`、生效路由、应用归属与上述开关状态，缺一则对应格无效；诊断 P0/P1/P2 捕获路由不得作为正式 N2 的捷径。现有端点排除默认生效、尚无关闭开关：这是**测量前代码先决项**，不是本稿允许临时无凭据绕过；修改后需证明 initial 与 recreate 两腿都未残留排除。

针对每个外层目的 IP，预先定义 VPN 已创建且有实际出包时的两个独立路由场景：(1) 数据面已就绪、默认路由 `0.0.0.0/0` 真正生效且内层正控入 TUN；(2) 默认路由按产品安全门尚未放开时，不使用开发期 `force_default_route = true` 偷放行，而采用事先审核的覆盖该目的端的**非排除**定向路由并用相同正控证明该目的确有进入 TUN 的可能。默认路由在可用 peer 与 WG dataplane 就绪前必须保持 withheld；不能为取证强行放开黑洞风险。针对 M/S 初始先于 create 的连接，后续在同一连接上再造业务流量检验保护跨 create；断流重拨时也必须检验真实覆盖路由。若场景 (1) 因产品状态未就绪、场景 (2) 因平台限制无法建立覆盖，相关格 `UNSAT`，不得由“没有 TUN 命中”推论 protect 有效。

## 4. 同窗 TUN 负证据与未保护正控

复用核心 `WgDevice` 双方向 TUN tee 的扫描能力，但生产流量不一定带自定义 marker：为每个 socket 身份建立可审计的协议/端点/时间关联，能用随机一次性 nonce 时注册**先于发包**（0034 曾因先发后登记漏报）；不能插入 nonce 的 TLS/TCP，保存送包源/目标四元组、精确时间、连接建连与应用交付记录，并在抓包/tee 上限定同一端点和窗口。重新分配或 NAT 端口变化时重建映射；歧义包不得归入零命中。TUN 两向监测须覆盖整个刺激窗口且采样非空，保留抓取起止、丢包统计、过滤器、扫描帧数与逐包命中；匹配的外层包在 `vpn-tun` 出现一次即该格 `fail/leak`，即使物理口也看到包。TUN 单方零命中只是**负证据**，须与同一身份的确实发送、正控、物理出口同时成立。

正式测量的未保护正控应使用**隔离的测试 socket**，在同一应用/VPN 网络上下文、同一覆盖路由、同一类目的 IP 上发送独特标记，预注册其 socket ID、目标、时间与独立接收器；该控制流不能被生产 fd、缓存、系统代理或其他节点复用。正控需在发送前注册 tee、随后能观察到同一标记从本机 `vpn-tun` 的 from-OS 帧，且内层目的/可选对端应答匹配。对端 `a2b_seen` 单独增加不算本机 TUN 正控（历史上可由其他节点转发）；仅凭超时或设备 TUN 字节增长也不算。对 TLS 无法制作同目标明文标记时，在相同路由覆盖与网络身份下用独立 UDP/TCP 控制目的作辅助，并明确其不能单独证明被测 TLS 四元组已被路由覆盖；应另用路由查询/可审查的同目标控制连接补齐，否则 `invalid/UNSAT`。控制 socket 严格限短窗、只发非敏感随机标记并有物理安全边界；不允许借其业务面成功代替生产流的 N2 观察。

## 5. 独立物理出口 oracle

每个被测真实包提供设备侧物理 NIC/路由观测（受限时明示）**加**独立的网络侧观测：可选 AP/路由器镜像、运营商出口可核对源 IP 的服务端监听日志、management/signal/relay 服务端连接账本、DNS resolver 回执与 STUN/peer 外侧日志。收集同窗精确时间、传输协议、目的和源/NAT 四元组、连接 ID/nonce、握手或回执；TLS 只能靠连接元数据和端点日志关联，不得声称 pcap 能解读 TLS 内层 Auth 帧。源 IP 必须被确认属于目标设备的本轮物理出口（允许 NAT，保存映射），排除宿主 Pod、另一 NetBird 节点或代理代发。当前主机处于 NAT Pod、无法接受外部 UDP 入站：W/I/D 不得以这个 Pod 的 UDP 收件缺失判失败或成功；正式轮使用可到达的外部 UDP echo/STUN/解析器、路由器镜像或具有请求 ID 的服务端日志，执行前先证实 oracle 可达且可归因。relay 数据面必要时结合客户端 TLS 连接、Caddy/relay 服务端日志和可审查的转发计数，避免容器健康探测伪装成会话。oracle 不可用、无身份映射或时钟偏差无法界定，格子判 `invalid/UNSAT`。

## 6. Fail-closed 故障注入

授权的测试制品加入可逆、分目的的注入点（`protect` reject、5 s 壳计时盒 timeout、late resolve、8 s 核心 supply timeout、陈旧 request ID、无物理 DNS/网络句柄、fd 关闭/dup 失败；如可实现另测成功 resolve 但平台生效延迟）。只在隔离的目标 socket 注入，保留动作顺序、fd/dup、errno/原因和物理/TUN 原始捕获；每种情况必须证明**该 socket 无未保护出站包**，不是只看到错误日志。成功恢复后**新建并重新 protect**，不把旧失败 fd 再用。

按模块分别核验：初始 signal 失败须停 connector、不 create；WG base 保护/feed 失败须销毁已创建 VPN；M/S/R 无供给或失败时拒绝裸 TCP 重拨；DNS 无物理 resolver/保护失败时不发查询且不退回系统解析；ICE 池某个失败允许候选减少、全池失败拒绝 gather，不许裸 UDP；recreate 时补给与补池必须使用**当前** `VpnConnection`，中间代际窗口拒绝请求；最终 destroy 时先停止存活发送者，不留失保护后出站间隙。fd 号复用与迟到 Promise resolve 另录竞争序列；如果 resolve 后物理证据表明保护尚未生效，应停止 N2 判定并返回 T0，不能靠任意 sleep 修饰。失败/中断行保存原始产物并记 `invalid`，不得静默重跑覆盖。

## 7. 生命周期、计数与机械判定

每行有 `ARMED`（采集器/路由/对照与网络就绪）→ 发送 → 精确 `CLOSE`；逐行记录 `socket_id`、壳原 fd→核心 dup→最终关闭的身份图、`protect_begin/settle`、feed/accept、首 connect/bind/send、recreate 旧/新 connection ID、网络 generation、路由快照与时钟误差。跨 create 检验 pre-create fd 后续仍出物理网；跨 recreate 检验全部存活 M/S/R/I/W（D 为新查询，不假定常驻 fd），随后触发新补给和 ICE 补池；切网两向记录旧 socket 收尾、新 socket 的物理源地址/接口与实际管理、信令重新注册。最终 VPN revoke 与受控 recreate 不混为一格，撤销后持续采集短窗并确认没有仍可发送的旧外层 socket。无法观察的生命周期转移不由其前后状态推断。

每格同时记录设备 `vpn-tun` from/to 帧和字节、可用的内核 `/proc` 接口读数、物理 NIC/路由器捕获包数、应用 socket 成功发送数、正控逐 nonce 命中数、服务端回执数和抓包掉帧；逐项注明来源与采样时间，不能把来自同一 tee 的自计数充当独立对账。统计 API 曾有采样/同源争议，仅作趋势辅证；不得用总字节差、零帧窗口或对端收到包替代单 socket 的路径归因。缺包/时钟偏差/解码失败显式记无效，不能拿互不相干计数相减凑吻合。

冻结判定器拟采取优先级：身份匹配的生产外层包命中本机 TUN、发现未保护首发或失败裸连 ⇒ `N2 fail`（即便其他格通过）；必要开关/路由/正控/流量/物理 oracle/生命周期缺件，或实现要求类未测 ⇒ `N2 UNSAT/inconclusive` 并列出类别、格子及原因；只有全部**实际实现且适用**的类与矩阵格通过、无泄漏、注入 fail-closed 且独立审查确认作用域，才可提议 `N2 reviewed-pass`，最终门级 pass 仍依治理审批。未实现类别独列 `not implemented`，不自动当作通过，也不伪装成失败；如果需求实际要求该能力则先实现。N6 独立填 verdict，依内层往返/默认路由 gate 等自己的证据，N2 未通过不会被 N6 的流量成功抵消。对冲突/歧义采最保守 `invalid/UNSAT`，不在看到数据后更改阈值。

## 8. Campaign 授权、执行与保密

正式轮另起**N2 专属 campaign 授权**，不是 0037/0038 的诊断授权沿用。授权需明写目标设备/无线调试地址核对、允许的 HDC argv 白名单、应用包及生产/实验 HAP 与恢复包、执行器和判定器冻结哈希、路由与注入开关的范围、每格动作/网络切换/预定回滚、证据目的地和保密/最小化、每种设备命令和重试的计数上限、预计总时长、唯一执行者、停止条件、sidecar 校验和消费状态。无线目标历史值 `192.168.50.199:37193` 仅为待复核，不构成现轮授权。执行器建议以 0037 的阶段白名单、argv-list HDC、逐命令记账和 SHA 登记为**设计样板**，新建 N2 专用脚本和判定器，不运行 0037 脚本、不复用其哈希/额度。采集含完整与应用范围日志时，在每格精确 CLOSE 后**先**即时备份 app-scoped 日志，再导出全量日志；CLOSE 窄查询建议每 5 s、最多 12 次/60 s，须写进新授权。N2 的采集器/日志分块与来源一致性应自测（历史 0037 的 34 块是旧设计，不复用作新轮常数）。任何未授权设备命令都不得以“预检必要”为由先跑。

**待独立裁决的授权冲突**：[治理时间窗口硬门](native-nx-governance.md#L138-L153)当前明确要求 `valid_from/valid_until`、主机和设备时钟≤60 s、15 分钟内重比对，且 hdc 不可达立刻停；较新的诊断轮建议在离线时最多 10 次 `tconn` 后停、授权不设固定过期、断开行允许一次保留两次证据的重试、固件小修记录/大修停。这些建议**不能擅自覆盖**现行治理硬门。新授权签发前须 T0/用户明确修订或逐条调和治理：若未修订，按较严旧门执行（不得对 hdc 不可达做 10 次重连尝试、不得无 `valid_until`）；先把允许的**唯一只读设备时间查询**纳入白名单，并定义如何在首次命令前合法读取，采集主机/设备时间及授权窗口原值，执行者先向主会话回报比对、获确认后才进入其它设备操作。若不可合法读取、窗口不足预计总时长、时钟异常/后退、sidecar 错误或授权已消费，即停止，不补签追认。任何后续许可的重试都必须写进新授权并把两份原始尝试均保留；离线与固件版本变化也需明确停止/续行条款。**本稿不授权任何重试或设备预检**。

预检核对设备电量/网络、AP 与 cellular、服务端日志权限、DNS/STUN/relay oracle、时间对齐和证据存储；涉及设备的预检同样待授权。证据最小化抓 IP/传输头、截短 snaplen 与必要 nonce，禁止保存 JWT、setup key、私钥、令牌、解密流量或凭据内容；产物脱敏、敏感扫描、逐件哈希/清单，原件不可因失败删改。执行后逐项恢复 HAP、网络与路由、日志级别及所有临时注入，记录恢复失败而非隐藏。
